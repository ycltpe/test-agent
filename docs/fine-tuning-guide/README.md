## 1. 微调是什么

### 1.1 一句话解释

**微调（Fine-tuning）** 就是：拿一个已经在海量通用数据上训练好的「大模型」，用你自己的小数据集继续训练它，让它学会你特定任务或领域的知识和技能。

想象模型是一个已经读完整个图书馆的大学生：
- **预训练** = 读大学，博览群书，拥有通用知识和语言能力。
- **微调** = 入职后的岗前培训，让他学会你公司的业务、术语、流程、写作风格。

### 1.2 核心原理

预训练模型已经学到了语言的通用表示。它的权重就像一张「世界地图」，微调则是在这张地图上，把某个特定区域（你的任务）放大、细化。

数学上，微调就是继续最小化损失函数：

```
θ* = argmin_θ  L(θ; D_task)
```

其中：
- `θ` 是模型参数
- `D_task` 是你的任务数据
- `L` 是任务损失（分类用交叉熵，生成用 next-token 预测损失）

训练时，模型根据你的数据不断调整权重，让输出越来越符合你的期望。

### 1.3 用一个比喻理解

| 概念 | 比喻 |
|------|------|
| 预训练模型 | 通用的大脑 / 地图 |
| 你的任务数据 | 岗前培训手册 |
| 损失函数 | 考试评分标准 |
| 优化器 | 老师，告诉你怎么改进 |
| 学习率 | 每一步改进的幅度 |
| 过拟合 | 死记硬背培训手册，不会变通 |
| 泛化 | 学到通用规律，能处理没见过的例子 |

## 2. 为什么需要微调

### 2.1 与提示工程（Prompt Engineering）的区别

| 方式 | 优点 | 缺点 | 适合场景 |
|------|------|------|----------|
| 提示工程 | 不用训练，快速尝试 | 受上下文长度限制，复杂任务难表达 | 简单任务、快速原型 |
| 微调 | 模型真正学会，输出更稳定、更专业 | 需要数据和算力 | 专业领域、高频任务、需要稳定输出 |

**关键区别**：提示工程是「教会模型临时记住」，微调是「让模型真正学会」。

### 2.2 与 RAG 的区别

| 方式 | 核心思想 | 优点 | 缺点 |
|------|----------|------|------|
| RAG | 检索外部知识，再让模型生成 | 知识实时更新，可解释 | 检索质量决定上限 |
| 微调 | 把知识注入模型参数 | 推理快，输出风格一致 | 知识更新需要重新训练 |

**最佳实践**：复杂系统往往是「微调 + RAG + 提示工程」三者结合。

### 2.3 微调能带来什么

1. **更懂你的领域**：医学、法律、金融等术语和表达更准确。
2. **输出风格一致**：客服话术、营销文案、代码风格统一。
3. **指令遵循更好**：让模型按你想要的格式、步骤、约束回答。
4. **减少幻觉**：在事实稳定的领域内，输出更可靠。
5. **更小更快**：可以蒸馏成小模型，部署到边缘设备。

## 3. 微调的三种常见类型

### 3.1 全参数微调（Full Fine-tuning）

**做法**：更新模型的所有参数。

**优点**：效果上限高，模型能深度适配任务。

**缺点**：
- 需要大量显存（训练 7B 模型可能需要 80GB+）
- 容易过拟合小数据集
- 训练好的模型文件很大

**适合**：数据充足、算力充沛、追求最佳效果的场景。

### 3.2 参数高效微调（PEFT）

**做法**：只训练少量新增参数，冻结原模型大部分权重。

**代表方法**：
- **LoRA（Low-Rank Adaptation）**：在注意力层旁加低秩矩阵，只训练这两个小矩阵。
- **Adapter**：在 Transformer 层之间插入小适配层。
- **Prompt Tuning**：训练一组「软提示」嵌入。

**优点**：
- 显存占用小（QLoRA 可在 24GB 显存训练 65B 模型）
- 训练速度快
- 一个基础模型 + 多个小适配器，切换方便

**适合**：大多数实际项目，尤其是资源有限的场景。

### 3.3 对齐微调（Alignment）

**做法**：让模型的输出更符合人类偏好、价值观和安全要求。

**代表方法**：
- **SFT（Supervised Fine-Tuning）**：用高质量指令-回答对训练。
- **RLHF（Reinforcement Learning from Human Feedback）**：基于人类反馈的强化学习。
- **DPO（Direct Preference Optimization）**：直接用偏好对优化，不需要训练奖励模型。

**适合**：聊天机器人、客服助手、任何需要「像人一样对话」的场景。

## 4. 微调流程六步法

无论用哪种方法，微调基本流程都一样：

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│ 1. 明确目标  │ → │ 2. 准备数据  │ → │ 3. 选择模型  │
└─────────────┘   └─────────────┘   └─────────────┘
       ↓
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│ 6. 部署使用  │ ← │ 5. 评估调优  │ ← │ 4. 训练模型  │
└─────────────┘   └─────────────┘   └─────────────┘
```

### 4.1 明确目标

先回答三个问题：
1. **模型要做什么任务？** 分类、生成、抽取、问答、代码补全？
2. **输入输出长什么样？** 写 5 个真实样例。
3. **成功标准是什么？** 准确率、F1、人工评分、用户满意度？

### 4.2 准备数据

数据质量决定微调上限。常见格式：

**分类任务**：
```json
{"text": "这部电影太精彩了！", "label": "正面"}
{"text": "完全看不下去。", "label": "负面"}
```

**指令微调**：
```json
{
  "instruction": "把下面这段话改写成正式邮件语气",
  "input": "嘿，明天开会别忘了带报告。",
  "output": "您好，谨提醒您明日会议请携带报告，谢谢。"
}
```

**数据准备原则**：
- 数据要覆盖真实场景
- 正负样本尽量平衡
- 训练集 / 验证集 / 测试集要分开
- 防止测试数据泄漏到训练集

### 4.3 选择模型

| 场景 | 推荐基座模型 |
|------|-------------|
| 中文 NLP 分类 | `bert-base-chinese`, `chinese-roberta-wwm-ext` |
| 多语言分类 | `distilbert-base-multilingual-cased` |
| 中文通用对话 | `Qwen2-0.5B/1.5B/7B-Instruct`, `DeepSeek-V2` |
| 代码 | `CodeQwen`, `DeepSeek-Coder` |
| 英文通用 | `Llama-3`, `Mistral`, `Gemma` |

### 4.4 训练模型

关键超参数：

| 参数 | 作用 | 常见取值 |
|------|------|----------|
| learning_rate | 学习步长 | 1e-5 ~ 5e-5（全参数）；1e-4 ~ 2e-4（LoRA） |
| batch_size | 每次更新看多少样本 | 8, 16, 32（显存允许越大越好） |
| epochs | 训练轮数 | 3 ~ 10（看验证集早停） |
| warmup_steps | 预热步数 | 总步数的 5% ~ 10% |
| weight_decay | 权重衰减 | 0.01 ~ 0.1 |
| lora_r | LoRA 低秩 | 8, 16, 32, 64 |
| lora_alpha | LoRA 缩放 | 16, 32, 64（通常等于或 2x r） |

### 4.5 评估调优

不要只看训练 loss！必须看验证集指标：
- 分类：Accuracy、Precision、Recall、F1
- 生成：BLEU、ROUGE、人工评分、LLM-as-Judge
- 通用：困惑度（Perplexity）

**早停（Early Stopping）**：验证指标不再提升就停止，防止过拟合。

### 4.6 部署使用

训练好后：
- 合并 LoRA 权重到基座模型（可选）
- 导出为 ONNX / GGUF / TensorRT 等推理格式
- 用 vLLM、TGI、llama.cpp 等框架加速推理
- 设置监控：输入分布漂移、输出质量、用户反馈

## 5. 微调的应用场景

### 5.1 垂直领域助手

- **医疗**：理解病历、辅助诊断、医学文献问答
- **法律**：合同审查、案例检索、法规咨询
- **金融**：财报分析、风控报告、投研问答

### 5.2 企业效率工具

- **客服**：继承企业话术，处理退换货、预约、投诉
- **销售**：写跟进邮件、生成报价单、分析客户需求
- **HR**：筛选简历、生成面试问题、回答员工政策

### 5.3 内容创作

- **营销文案**：符合品牌调性的广告、社媒帖子
- **技术写作**：产品文档、API 文档、Release Notes
- **教育**：个性化答疑、题目讲解、作文批改

### 5.4 代码与开发

- **代码补全**：按公司代码风格生成代码
- **代码审查**：发现潜在 bug、安全漏洞
- **测试生成**：根据需求自动写单元测试

### 5.5 特定格式输出

- **结构化输出**：强制输出 JSON、XML、Markdown 表格
- **多轮对话**：保持角色一致性、上下文记忆
- **长文本处理**：论文摘要、会议纪要、报告生成

## 6. 代码实战一：中文情感分类

见 `finetune_classification.py`。

这个例子：
- 使用 `distilbert-base-multilingual-cased`（多语言，支持中文）
- 在一个极小的中文情感数据集上微调
- CPU 也能跑，适合新手理解完整流程

### 运行步骤

```bash
cd docs/fine-tuning-guide
pip install -r requirements.txt
python finetune_classification.py
```

### 代码重点解析

1. **数据准备**：把文本和标签变成模型能理解的 `input_ids` 和 `labels`。
2. **模型加载**：从 Hugging Face 加载预训练模型。
3. **训练配置**：设置学习率、批次大小、训练轮数。
4. **Trainer**：Hugging Face 的 `Trainer` 封装了训练循环。
5. **评估**：用验证集计算准确率。

## 7. 代码实战二：LLM 指令微调（LoRA）

见 `finetune_lora_llm.py`。

这个例子：
- 使用 `Qwen2-0.5B-Instruct`（轻量中文大模型）
- 用 LoRA 做指令微调

### 运行步骤

```bash
pip install -r requirements.txt
```

### 代码重点解析

1. **LoRA 配置**：用 `peft` 库配置 `LoraConfig`，指定要训练的层。
2. **数据格式化**：把指令数据变成对话格式。
3. **SFTTrainer**：TRL 库提供的指令微调 Trainer。
4. **推理测试**：加载训练好的 LoRA 权重，测试模型输出。

## 8. 常见坑与对策

| 坑 | 现象 | 对策 |
|----|------|------|
| 过拟合 | 训练集 loss 降，验证集 loss 升 | 增大数据、降低学习率、早停、加正则化 |
| 灾难性遗忘 | 模型忘了通用知识 | 混合通用数据、使用 replay buffer、LoRA 只训少量参数 |
| 数据泄漏 | 测试集出现在训练集 | 严格划分数据、去重、时序数据按时间切分 |
| 学习率太大 | loss 震荡不下降 | 降低学习率、加 warmup |
| 学习率太小 | loss 几乎不变 | 提高学习率、检查梯度是否回传 |
| 显存不足 | OOM | 减小 batch size、用 LoRA/QLoRA、梯度累积、开启 gradient checkpointing |
| 输出不稳定 | 同样输入不同输出 | 调低 temperature、固定 seed、用 greedy decoding |
| 幻觉严重 | 模型胡说 | 增加事实数据、RAG  grounding、RLHF/DPO 对齐 |

## 9. 下一步学习路线

1. **跑通示例**：先把 `finetune_classification.py` 跑起来，改改数据看效果。
2. **换更大的模型**：尝试 `Qwen2-1.5B` 或 `DeepSeek-R1-Distill-Qwen`。
3. **尝试 LoRA**：跑 `finetune_lora_llm.py`，理解 PEFT 的优势。
4. **准备真实数据**：用你的业务数据替换示例数据。
5. **系统学习**：
   - 阅读 Hugging Face Transformers 文档
   - 学习 PEFT、TRL 库
   - 了解 DeepSpeed、FSDP 分布式训练
6. **进入 BMad 规划流程**：如果你要把这个想法做成产品，下一步可以用 `bmad-product-brief` 整理产品概念。
