# 微聊首响 Agent（安居客微聊 MVP）

## Why

安居客微聊链路中，买家首条消息的真人响应时间为分钟级，高峰/夜间达小时级，高意向客户因此流失；经纪人 60-70% 的微聊时间消耗在"在吗/什么价/还有吗"这类可标准化的高频问答上；价格、学区等敏感问题的人工回答口径不一，存在合规风险。这是一个要解决的痛点：在买家消息到达后 3 秒内给出准确、合规的首次响应，完全替代真人首响，仅在命中预设红线时转交经纪人。MVP 不追求"最聪明的 Agent"，追求"最快、最稳、最守规矩的 Agent"。

## Capabilities

- **CAP-1 意图分类**
  - **intent:** 系统对每条买家文本消息输出单一意图标签与置信度分数，作为后续路由的唯一依据。
  - **success:** 在人工标注测试集（≥1000 条，覆盖全部 9 类意图，含指代改写样本）上分类准确率 ≥ 90%；分类延迟 P99 < 50ms（含指代消解的端到端口径，见 CAP-11）；结果写入会话状态（键 `weiliao:session:{session_id}:intent:{turn}`）。
- **CAP-2 重复追问识别**
  - **intent:** 识别同一 session 中针对同一意图的第 2 次及以后消息为 Follow-up Query，并维护追问计数。
  - **success:** 识别准确率 ≥ 95%（同义改写视为同一意图，如"还在吗"与"没卖掉吧"）；计数存于 Redis，TTL 与会话一致（30 分钟）；同意图追问 ≥ 3 次时 100% 触发转人工。
- **CAP-3 硬触发转人工**
  - **intent:** 命中任一硬触发条件（红线意图、图片/语音输入、同一意图追问 ≥ 3 次、负面词汇）时，立即将会话转交经纪人工作台，同时向买家发送安抚通知。
  - **success:** 硬触发命中 100% 转人工、零生成回答；买家收到"已为您转接经纪人，请稍候"类通知；转交指令送达经纪人工作台延迟 P99 < 5s；漏转率 < 15%（转人工判定准确率 ≥ 85%）。
- **CAP-4 事实卡片缓存**
  - **intent:** 以"意图 + 房源 ID + 房源状态 + 价格分桶"为 key，缓存事实卡片（房源状态、当前挂牌价 10 万分桶、对口学校、最近 3 轮对话摘要），由模板引擎或 LLM 在响应组装时引用组装——缓存的是事实而非最终文案。
  - **success:** 缓存拦截率 ≥ 80%（口径：L1 与 L0 命中均计入分子，基数为全部首次消息，压测验证）；TTL 5 分钟；房源状态变更经 Kafka 事件主动失效；事实变更以 Kafka 事件为唯一权威写入路径。
- **CAP-5 重复追问禁走缓存**
  - **intent:** Follow-up Query 必须进入 LLM 链路，结合对话上下文生成安抚性回应，避免机械化重复应答。
  - **success:** 同 session 同意图第 2 次消息 100% 进入 LLM 链路（Langfuse trace 可验证）；LLM 响应与首次缓存响应文本相似度 < 0.8。
- **CAP-6 LLM 受控生成**
  - **intent:** 对未命中缓存且非红线意图的消息，调用 OpenAI（gpt-4o / gpt-4o-mini），prompt 包含事实卡片、对话上下文与生成约束（不得承诺价格可谈、不得承诺学区名额、不得使用"最""第一"等违禁词）。
  - **success:** 生成内容不虚构事实卡片之外的房源数据（价格、面积、学区）；首 token 到达 P99 < 1.5s。
- **CAP-7 生成内容审核**
  - **intent:** LLM 生成内容 100% 经风控中台后置审核通过后才可发送给买家；审核不通过时切换至模板兜底应答。
  - **success:** 审核通过率 ≥ 95%（上线前压测基线，作为全量放行门槛）；审核不通过时买家收到模板兜底响应、服务无中断；未审核内容零外发。
- **CAP-8 OpenAI 故障降级**
  - **intent:** OpenAI 返回 429 / 5xx / 超时（> 1.8s）时自动切换至模板兜底；恢复后按 10% 步进逐步切回。
  - **success:** 降级切换时间 < 100ms；降级期间服务可用性不降级（不向买家返回 5xx）；降级事件写入 Langfuse trace 并触发监控告警。
- **CAP-9 AI 身份披露**
  - **intent:** Agent 全程以"AI 助手"身份应答并持续可见 AI 标识，绝不伪装真人经纪人；转人工后标识切换为经纪人姓名/头像。
  - **success:** Agent 响应 100% 携带 AI 标识；转人工后标识无残留；生成文本不含"我是这套房的经纪人"或等价表述（由风控审核把关）。
- **CAP-10 会话状态一致性**
  - **intent:** 维护买家会话状态（意图历史、追问计数、事实卡片引用、handoff 状态）于 Redis，所有服务实例共享，多轮对话上下文一致。
  - **success:** 会话 TTL 30 分钟；多实例并发读写无竞态（Redis 原子操作或分布式锁）；会话过期后重新发起对话状态从零初始化、无残留。
- **CAP-11 指代消解**
  - **intent:** 在意图分类之前，将会话上下文中已知的实体引用（"它""这套""那套""上面说的"等）归一化为显式引用，输出自包含的消解后消息与引用元数据，作为意图分类、重复追问判定与 LLM 生成的唯一输入。
  - **success:** 房源指代消解准确率 ≥ 95%（人工标注测试集，含指代类样本 ≥ 20%）；消解延迟 P99 < 10ms；无法确定先行词时保留原文进入意图分类，不阻塞、不转人工（PRD FR-11）。

## Constraints

- 首响延迟 P99 < 3s 为硬指标：从买家消息到达至买家收到响应的端到端耗时，不得以牺牲延迟换取模型质量。为在此预算内容纳 LLM 链路，OpenAI 端到端超时阈值收紧为 1.8s（含 1 次内部重试）；风控审核超时（默认 500ms，可调区间 300-800ms）视为不通过并切换模板兜底。
- Agent 以独立 Python 服务接入：既有 SpringBoot 微服务体系不动，买卖双方消息经 Kafka 解耦，转人工以 Kafka 单向指令与 SpringBoot 经纪人工作台对接。
- OpenAI 配额为有限资源：任何模型层优化不得以显著增加 token 消耗为代价。
- 合规：AI 身份必须明确披露，不得以任何形式伪装真人经纪人。
- 全链路数据交换统一为单一 Pydantic 信封模型（session_id、house_id、turn、intent、timestamp、trace_id、message、resolved_message、coref、media_type 十字段，schema 见 [glossary.md](glossary.md)）；管道过滤器间仅通过信封传递，禁止跨过滤器私有耦合（细节见 [architecture-decisions.md](architecture-decisions.md) AD-1）。
- 追问计数的权威值只存于 Redis，任何进程内缓存（L1）快照不得作为判定依据；硬触发判定一律读 Redis 权威值（AD-4/AD-5/AD-12）。

## Non-goals

- 议价辅助 Agent（V2+）
- 经纪人数字分身（人设模拟、语气克隆）
- 多级模型降级链（DeepSeek / Qwen 接入，V2；MVP 仅 OpenAI + 模板兜底）
- 软触发（置信度低于阈值转人工），仅硬触发
- 图片/语音理解与生成，此类输入直接转人工
- 带看调度、签约材料等后置链路 Agent；转人工后会话历史摘要生成（经纪人工单增强）
- 业务转化指标承诺（首响时间对带看率的影响由产品团队另行评估）

## Success signal

买家发出首条消息 3 秒内收到准确、合规的首响：80% 的高频问题经缓存与模板在零 LLM 调用下应答（缓存拦截率 ≥ 80%），OpenAI 配额耗尽或故障时模板无缝承接、服务不返回 5xx。压测与 Langfuse 全链路 trace 可对该信号逐一验证，模型层指标（意图准确率、审核通过率、转人工判定准确率）达标后方可全量放行。

## Assumptions

- 意图分类器具体选型（规则引擎 / gpt-4o-mini zero-shot / 微调小模型）留待第 2 周语料标注后决定；本 SPEC 只约束接口边界（单一意图标签 + 置信度，见 [glossary.md](glossary.md)）。
- 指代消解实现选型（规则模板归一化 / 轻量序列标注模型 / LLM 改写）留待第 2 周语料标注后决定（PRD OQ-5），本 SPEC 只定接口边界（AD-11）；若倾向 LLM 改写方案，须另行论证其 10ms 延迟预算可行性。
- 主模型迁移（gpt-4o → gpt-6-luna）为已定 Deferred 项：gpt-4o 全系列将于 2027-01-14 从 API 关停，迁移前须完成替代模型验证与灰度；模型名经配置注入（alias 指向当前快照，禁硬编码），详见 [stack.md](stack.md)。
- 买家"用户关注标记"功能（UJ-2）与经纪人工作台的接口可行性待确认，暂未承载于任何 CAP。

## Open Questions

- 风控中台的 QPS 上限未确认：若其无法承接 Agent 全量后置审核流量，是否引入本地敏感词缓存前置层？
- "负面词汇"硬触发词库由谁维护？目前无明确 owner，需与客服团队确认。
- 会话过期时间 30 分钟是否合理？需真实微聊会话间隔数据验证。
- 部署拓扑（K8s vs 公司 PaaS、实例水平扩展、可用区冗余）待运维/架构评审决策；逻辑架构已约定实例无状态。
